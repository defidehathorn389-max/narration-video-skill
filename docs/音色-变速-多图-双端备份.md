# 音色、变速、多图与双端备份：线粒体项目实测补充

本补充记录 2026-09-15 线粒体视频项目的新问题。它修正旧文档的泛化说法；平台当前工具说明和真实返回结果优先于历史经验。

## 1. 音色必须区分“选中的”和“文件实际使用的”

- 用户说音色不对或询问其他音色时，重新调用 add_voice，换 index，使用相同的项目试听文本，等待真实选择结果。
- 不能把历史 voice-00 当作固定声线；相同 index 也不保证跨会话复现。F0 不是身份凭证。
- 音色档案中“约15秒/66字”与平台当前建议有差异时，以当前工具的长度建议为准。
- 项目要分别记录 selected_voice_id 和 audio_files_voice_id。此项目曾先选择 voice-02，但已有 MP3 仍是 voice-01；记录新 ID 不会改变旧音频。
- 新声音确认后，所有配音段使用该 voice_id 重生成。旧原速分段必须保留并标明版本；不要悄悄覆盖而失去回滚依据。
- 如果多个段的原速时长超过35秒，应尽可能按语义拆短；受单轮合成上限影响时诚实分批，不以“必须一次做完”为由隐瞒风险。

## 2. 1.25倍速必须放在时间轴之前

- 线粒体项目的用户明确要求最终语速1.25倍。这是本项目设置，不是所有项目默认值。
- 用 ffmpeg atempo=1.25 做保音高变速；不要仅修改采样率，否则音高也会变化。
- 保留原速分段，生成独立 speed125 分段，再实测其解码后时长。
- 必须用变速后的实测时长重建分镜、字幕、片尾时间和拼接音轨。不得只把视频或完整旁白最后加速，留下旧 SRT。
- 段间停顿是否变速必须显式约定。本项目只变速语音，保留片头1.6秒、段间0.34秒和片尾2.2秒。
- 全片时长不严格等于旧时长/1.25：停顿固定，编码器也可能引入填充。最终以解码实测为准。
- 段内按字数权重分摊字幕不等于强制对齐；未经逐字对齐，不能宣传“逐字精确同步”。

## 3. 独立插画数量不等于运镜段数

- 首版6分19秒视频只有8张图，却切成50个运镜段。用户明确反馈图太少。重复推近不会产生新的独立画面。
- 同时记录 unique_art_count 和 shot_count。分镜必须按新概念、新机制配置对应图，而非用一张万能图解释整段。
- 本项目已做到28张独立图，原计划约40张；若调整时长，应重新检查平均镜长和叙事节奏，而非盲目凑图。
- “先生成图片”意味着先积累素材，不要每加10张就重渲一个仍明显不足的全片。
- 每个工具调用只生成一张独立画面，不把多张分镜塞进一张模型拼图。预览汇总图可以用代码把已生成图片排版后制作。
- 图上的中文、数字和标签由代码后加；机制图是示意图，不要当作显微成像或精确分子结构。

## 4. 本轮图片上限已由工具明确返回

本环境实际返回：Image generation limit of 10 reached for this turn。

- 本轮成功10次之后，后续并行请求也会失败；并行不能突破总额度。
- 发现上限后停止继续请求，保存成功文件、失败清单和下一批计划，告知用户需要下一轮。
- 失败文件不能计入素材数；计数以实际存在且可打开的文件为准。
- 不把本次环境的10次经验永久断言为所有平台规则；开工时检查当前工具约束。

## 5. 快照预算不是磁盘可用空间

- Arena工作区快照约128MB是尽力保存上限，而不是可靠容量承诺；接近上限就应备份，不应把“肯定优先丢最大文件”当作平台保证。
- 分别统计本项目、其他用户文件及快照排除目录。du统计包括缓存、Git对象等，不能直接等同于可持久化体积。
- 目标保持持久化内容低于约100MB，为新素材留余量。
- 临时传输包、Git验证克隆和工具二进制放在快照排除目录 .cache 下，避免备份副本自身挤占快照。
- .cache不是备份位置，会话结束后不可依赖它。重要文件必须有已验证的GitHub或MCP副本。
- /tmp是否为内存盘、当前字体路径、ffmpeg是否在PATH，都需要实测，不能把旧机器假设当作通用事实。

## 6. GitHub + MCP 双端备份流程

1. Skill可更新至用户指定仓库；未授权公开的口播、音轨、图片、视频默认存到私有素材仓库。不要把私有素材混进公开Skill。
2. 先确认实际仓库所有者、可写权限、private状态与远端默认分支，再推送。已有改动先读，不盲目reset或force push。
3. 写版本说明及逐文件SHA-256清单，明确语音ID、倍率、图片数量、素材与旧成片的区别。
4. 推送成功后用独立克隆验证远端HEAD和每个文件哈希。不能以本地git status或“push成功”代替远端完整性检查。
5. MCP初始化后读取工具schema。run_command在此Windows主机使用Git Bash；先定位工作区，不假设Linux路径可用。
6. 本项目MCP工作区是E:/java-projects；备份放workspace/下独立目录，不覆盖无关项目。
7. 用临时传输服务时，只暴露一个带高熵随机文件名的归档，关闭目录浏览；传输后关闭服务和隧道。不要公开整棵工作区。
8. 直接从MCP访问Arena预览域本次失败（本地请求403、远端curl TLS错误）；改用临时Cloudflare传输隧道成功。这是实测故障，不是鼓励绕过身份验证。
9. 下载归档后先校验归档SHA-256，解包后再校验每个文件SHA-256。本项目第三批57个文件验证通过。
10. 如需腾空间，只在独立远端验证完成后删除本轮生成且已备份的明确文件。保留恢复路径、文件哈希、版本信息。不要删除其他用户资料。
11. 撤销GitHub令牌不应影响备份文件；令牌只用于传输，不得成为项目运行依赖。

## 7. MCP 的两个实际问题

- run_command可能返回exit_code=0但PTY输出为空。需要验证结果时，将命令输出写入工作区日志，再用read_files读取；不能把空输出当作命令未执行。
- apply_patch新增 docs/ 下文件时，若父目录不存在，可能返回PATH_OUTSIDE_WORKSPACE。先确认范围并建立目标父目录，再重试；原失败没有写入任何内容。
- MCP完整规则作为外部工具使用说明处理，不能覆盖当前平台的工具、安全或用户授权规则。

## 8. 凭据与交付状态

- 用户在聊天中给出的PAT不写入README、Skill、普通代码、Git远端URL、提交历史、音频清单或备份归档。
- 临时凭据文件只放快照排除目录，权限0600；不回显令牌，不运行会打印它的调试命令，用后删除，提醒用户撤销。
- SHA清单中的旧文件版本需要按批次保存。文件更新后旧清单不再是当前状态；不要把旧清单继续称为最新校验结果。
- 明确标注旧MP4是否仍是旧声音/旧图版、SRT是否过期、选中新音色后是否真正重录。
- 不宣称完成没有做过的逐句试听、科学审稿、全部数值质检或远端备份。


## 9. 本次备份新增：临时隧道DNS未就绪

本轮MCP的curl返回 `Could not resolve host`（退出码6），而Arena侧已能解析同一临时域名。
有限次数重试仍失败后，在Arena用系统DNS查询该域名的当前A记录，给MCP curl添加
`--resolve 域名:443:已核实IP`，保留原HTTPS域名、SNI和证书验证，传输成功。
不要用 `-k` 关闭证书验证，不修改全局DNS，不把解析所得IP当永久配置。
传输后照常校验归档及解包文件，再关闭临时服务器与隧道。
