# GitHub加密凭据与逐次询问规则

这是用户明确要求的凭据使用流程，适用于读取本Skill的后续助手/模型。

## 最新规则：每会话一次，不是每批次一次

用户最新明确要求：**当前会话只提供一次有效口令，已经主动提供就不再追问。** 这替代旧的按操作批次、仓库或工具调用重复询问规则。

1. 先简短说明本会话的目标仓库及操作范围；用户在当前会话主动提供口令，就视为已提供。
2. 同会话内、用户已授权范围内可在当前上下文或进程内存中复用；常规进度读取、保存、提交、推送、校验自动进行，不反复弹窗。
3. 每次实质性回复结束前保存并推送有变化的项目进度，不等到用户关闭窗口。无变化不做空提交。
4. 不跨会话继承授权，不从其他/已结束会话挖掘秘密；不将口令/token写入工作区、长期摘要或仓库。
5. 新增未授权目标、改变可见性、删除或强推等仍确认操作范围，但不重新索要已有口令。
6. 口令错误等待用户主动更正，不循环重试。环境丢失凭据时保存进度并说明未同步，不假装成功。

完整规则：https://github.com/defidehathorn389-max/session-handoff-skill/blob/main/SESSION_POLICY.md

## 密文定位

- 本工作区默认文件：`/home/user/credentials/github-token.enc.json`。
- 工具：`scripts/credential_vault.py`；依赖`cryptography`。
- 若换环境，先定位用户提供的加密文件；缺少文件时询问文件位置或请求上传密文，不声称只靠Skill就能恢复凭据。
- **公开Skill仓库只包含规则和工具，不自动提交密文文件。** 密文备份也应优先进入用户指定的私有存储。

## 存储与使用要求

- AES-256-GCM认证加密；每次加密使用新的16字节随机盐和12字节随机nonce。
- scrypt派生32字节密钥：N=131072、r=8、p=1，约128MiB内存成本。
- 文件格式版本、用途、算法、KDF参数及nonce作为AAD认证，篡改不能静默解密。
- 口令不保存到工作区、Skill、配置、备注、备份、命令历史或环境文件；不存口令提示或额外的口令哈希。
- 密文文件中不会保存明文token；不要另外保存明文副本。盐、nonce和密文SHA256可以公开用于恢复/校验，它们不是解密口令。
- token仅在本会话授权范围内的进程内存中使用，进程/会话结束后清理临时通道。不打印到stdout/stderr，不放入命令行参数、Git远程URL或Git配置，不开启会记录Authorization头的调试日志。
- 网络错误只输出经过脱敏的状态信息。需要Git操作时采用不落盘的短期凭据注入；没有安全方案就停止，不为了便利创建长期明文令牌文件。

## 终端使用

```bash
python -m pip install cryptography
python scripts/credential_vault.py check --vault /path/to/github-token.enc.json
```

CLI使用隐藏终端输入，拒绝通过参数、环境变量或管道输入口令；没有“打印明文token”命令。

助手运行环境没有交互终端时，只能在用户完成本次授权并提供口令后，调用库函数在短命进程内解密，随后直接执行获准操作；不要创建包含真实口令的脚本文件。不要把工具调用输入误称为独立的秘密输入通道。

## 安全边界

- 本文件是操作规则，不能保证任意模型都会遵守；密码保护来自密文本身。
- 聊天中已经提供过的token/口令仍可能存在于聊天记录、工具调用记录或平台日志中。文件加密不能撤回这些内容，也不能保证Python内存副本被彻底擦除。
- 想消除聊天暴露风险，应撤销旧token，在自己的电脑上创建新token并通过隐藏终端输入加密；不要把新token和新口令再次一起写入聊天。
- 加密和本地解密检查成功，不代表GitHub token仍有效或拥有足够权限。联网验证要在明确授权范围内进行；同会话已提供口令不再次询问。
- 忘记口令无法从密文恢复token；应撤销/重新生成token后创建新密文，不提供绕过机制。
