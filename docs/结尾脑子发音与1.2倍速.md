# 固定结尾「脑子」发音与当前1.2倍速规则

本文件记录用户多次亲耳指出的真实问题，不以ASR未检出为理由否定用户反馈。当前线粒体项目全局语速为 **1.2倍**，替代之前的1.25倍；历史文件名与实测数据不改写。

## 1. 永久加入发音回听清单

固定结尾：

> 独立思考，从看清自己脑子里那套系统开始。我们下期见。

- 「脑子」读 **nǎo zi**：脑是第三声，子通常为轻声。
- 连读时，第三声在轻声前常呈低降/半三声；不要要求每次都完整先降再升，更不能把它机械抬成第二声。
- 不能用固定F0值证明正确；音高范围随声线、上下文、语速变化。声调、元音、韵律最终需要真实回听。
- ASR可能把声调不自然的音频仍正确识别为「脑子」。文字识别成功不等于发音通过。
- 用户已经指出错读时，该旧片段标记为「用户确认有问题」，禁止将它继续当作通过样本复用。

## 2. 固定结尾优先独立合成

不要把固定结尾压在一个很长的TTS语段末尾。本项目采用：

1. 「独立思考，从看清自己」
2. 「脑子里那套系统开始。」
3. 「我们下期见。」

- 问题词位于新片段开头，降低长段尾部韵律退化影响。
- 不在真正发声文本里加入「请读第三声」「nǎo」或括号提示，避免把指导语读进视频。
- 不改口播原词。分段合成后只修剪首尾静音；「自己」和「脑子」之间保留很短、自然的连接，不制造生硬断句。
- 保存旧片段、新的独立原速片段、拼接方案及新结尾试听片段，方便比较和回滚。
- 如新片段仍被用户指出有问题，继续换切分或重新生成；不要以「机器已通过」拒绝修改。

## 3. 替换旧结尾的安全边界

- 先定位原音频中固定结尾之前的真实静音区，再在静音区内下刀，不能按字幕估计直接切掉前一句尾音。
- 本次原速第8段中，上一句之后的静音实测为30.648958–31.918083秒；切点30.85秒。这个数值仅适用于该音频，不可复制到其他版本。
- 解码PCM后拼接，避免MP3按任意字节或不精确帧边界直接截取。
- 修正后重新测量该段时长，再处理1.2倍速；不从旧1.25倍音轨简单再变速并沿用旧时间轴。
- 全部字幕和镜头重新依据新音频定位。生成速度修正版时保留清楚的版本名，别覆写旧文件后仍沿用旧SHA清单。

## 4. 当前速度与验收状态

- 当前用户选择：voice-02，1.2倍速。不是1.25，也不是播放器临时加速。
- 使用atempo=1.2保音高；保留原速素材。
- 片头/段间/片尾静音按项目约定独立处理；拼接语段后的实际时长须实测。
- 本次已将旧问题结尾替换为独立新生成片段。新发音在没有真实回听确认前，只能说「已重配替换、待回听」，不能写「发音全部修复并验收通过」。
- 每次换音色、改变语速或重生成结尾，都重新回听「脑子」，不要复用上一版本的通过状态。

## 5. 封面与分镜额度

- 封面也是图像生成任务，会占用本轮图片额度；生成背景后用代码加中文标题，不让图像模型写长中文。
- 四张封面背景加六张分镜正好是本环境一轮10次调用；不能同时承诺再生成10张分镜。
- 标注找到的是MP4、工程代码还是仅参考主题；不能把没有定位到的第三个视频假称已找到。
- 统一封面系列的配色、字号、安全区和焦点，但每个主题要有不同的机制视觉，不能只换标题。
