# 验收、交付与 Git 发布

## 内容验收

- [ ] 题目规则和现实/理想化假设完整。
- [ ] 解答独立验证，所有分支覆盖。
- [ ] 动画状态来自同一数学模型，没有为了好看改掉答案。
- [ ] 没把“时间”画成“长度”的错误等比例关系。
- [ ] 题干中的禁止条件与演示界面不矛盾；解释用时钟不等于角色借助钟表。
- [ ] 没有未经依据的爆款保证、正确率、逐帧相似度数字。

## 视觉与运动验收

- [ ] 16:9 横屏、约两分钟，非竖屏卡片模板。
- [ ] 灰底、黑白人物、少量黄色重点元素。
- [ ] 主道具在旁白期间有相关动作，不只是人物摇摆和字幕变换。
- [ ] 关键帧无文字越界、火焰压字、标签被物体挡住。
- [ ] 同一对象身份与位置变化能看懂。
- [ ] 封面不提前提示解题答案。

## 技术验收

- [ ] 视频真实解码为 1920×1080、30 fps、约 115–130 秒。
- [ ] 有 H.264 视频流和 AAC 音频流，yuv420p。
- [ ] 全片解码返回 0，无损坏帧错误。
- [ ] MP4 faststart，适合在线播放。
- [ ] 监听首尾和转场，无尾音截断或明显爆音。
- [ ] 字幕与解题动作的关键转折同步。

脚本 `validate_video.py` 能验证一部分技术条件，不验证谜题正确、实际听感或动画密度。不要将“解码通过”描述为“全部质量通过”。

## 最终交付

使用 `present_file` 或等价功能打开主 MP4。简洁说明：题目、横版分辨率、时长、配音与动画特点。可附封面和 SRT 链接；不把原始日志、草稿分镜当主交付。

## 凭据处理

如果用户在聊天中发来 GitHub token 或其他密钥：

1. 不复述完整值，不写入文件、代码、日志、远程 URL、环境配置或文档。
2. 提醒立即撤销该已暴露凭据，不在聊天中发送替代令牌。
3. 目标仓库地址与授权凭据是不同信息；仅有令牌不能知道“放到哪里”。
4. 请求仓库 URL、目标分支或安装目录。使用已连接的安全 GitHub 集成、OAuth 或用户本机凭据管理器。
5. 本地 Skill 包不依赖任何发布凭据即可制作。

不要通过枚举用户账号或仓库猜测其目标，不把令牌当目的地址。

## 推送前确认

- 目标仓库 URL、分支。
- 作为独立仓库，还是放入 `skills/logic-animation-video/`。
- 是否允许创建分支/PR；是否已有同名文件。
- 仓库是公开还是私有，生成资产是否适合分发。

首次尽量使用功能分支和 PR，不强推，不删除已有内容，不自动公开新仓库。未完成推送时明确说“本地包已完成，尚未上传”。

## 安全发布示例

以下只在目标已确认且 Git 已安全认证时使用。不要在 URL 中拼接密码或令牌。

```bash
git clone https://github.com/OWNER/REPO.git
cd REPO
git switch -c add-logic-animation-skill
mkdir -p skills/logic-animation-video
# 将 Skill 包的源文件复制到上面目录；避免带入 deliverables、生成缓存和音频中间文件。
git add skills/logic-animation-video
git diff --cached --stat
git diff --cached --check
# 检查暂存内容不存在凭据后，再提交并推送。
git commit -m "Add Chinese logic animation video skill"
git push -u origin add-logic-animation-skill
```

如平台有专门 GitHub 工具，按其授权边界使用，不必执行上述 shell。公开发布前由仓库所有者确认许可证；本包不会擅自给第三方参考视频或生成资产宣称版权授权。
